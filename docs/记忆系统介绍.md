# 一个会遗忘的 AI：记忆系统的设计与实现

> 对于我个人来说，重要的并不是记住所有，而是仿真一个有思考的个体。

受到抖音上大家对上下文讨论和已有项目的启发，我做了一套给聊天 AI 用的记忆系统。它不追求把更多聊天记录塞进上下文，而是让 AI 像人一样记住、遗忘、在某个时刻突然想起。

项目开源：https://github.com/xwx0708/humanlike-ai-deepseek

---

## 一、出发点：长上下文不是答案

主流做法是把上下文做得越来越长：128K、1M。但没有人能在脑子里同时摊开一百万字。人的长期记忆容量巨大，却是有损的、会重构的；一次能放在意识里的只有很少几件事。

大模型恰好相反：上下文是逐字精确的短期记忆，长期记忆冻结在权重里。它缺的是一层**能持续写入、会遗忘、会重组的情景记忆**。

所以这个系统把"思考"分成两部分：

- **当下**：正在进行的对话，交给思考模型集中处理。
- **非当下**：一片**概率海**。每段记忆不是"在或不在"，而是以某个强度存在、以某个概率被想起。

整体分三层：当下（上下文）→ 概率海（自然聊天时"记得什么"）→ 档案库（被遗忘的原文，平时碰不到）。

## 二、遗忘曲线

每段记忆（片段）有一个强度 S。刚记下时 S = 1，之后按指数衰减：

```
S(t) = 0.5 ^ (Δt / H)
```

H 是半衰期：每过一个 H，强度减半。半衰期从基础值出发，被情绪和重要性放大：

```
H = 7 天 × 10^a × 5^i × 首尾加成 × 潜意识调整
```

- **a：相对唤醒度**（0～1）。这件事比用户平时的情绪基线强烈多少。依据是情绪增强记忆巩固（杏仁核效应）：惊吓、狂喜的经历记得特别牢。最强烈时半衰期放大 10 倍。
- **i：重要性**（0～1）。平淡但不能忘的事（过敏、家人名字）靠它保住，最多放大 5 倍。
- **首尾加成**：一场对话的第一个和最后一个片段半衰期 × 1.5（首因效应、近因效应）。
- **潜意识调整**：后台模型根据新信息拉长或缩短某段记忆的半衰期，单次不超过 3 倍、累积不超过 5 倍。只有事件已经完结，才允许缩短。

**提取巩固**：一段记忆在回复中被真正用到时，S 回到 1，半衰期变为

```
H ← H × (1 + (1 − S))
```

越是快要忘掉时被想起，巩固越多（最多翻倍）；刚说过又提，几乎不巩固。仅仅"浮现"不算用到，避免强记忆自我强化、越来越常出现。

大致效果：平淡小事约三周遗忘；有点情绪的事约两个半月；很强烈的事半年以上；再叠加重要性或反复提起，可以保留数年。

### 记忆时钟

Δt 不按日历时间算，按**对话时间**算：

- 对话进行时，记忆时间以 10 倍速流动；
- 最后一条消息后 25 分钟，流速降到 1%；
- 再过 24 小时，完全停止。

所以用户三个月没来，回来时 AI 不会把一切都忘掉；遗忘只发生在"相处"的时间里。

## 三、记忆系统的结构

**片段与事件线**。对话结束后，潜意识模型把消息切成片段（一个子话题），给每个片段打唤醒度、效价、重要性，并把它挂到一条**事件线**上（同一件事的前后片段，可能跨越几天）。夜里会合并重复的事件线：例如"妈妈住院"和"母亲的肺炎"合成一条。

**常驻栏**。有些事应该一直记得：
- 免竞争：用户的真实信息（画像出处）、用户明确要求记住的、在至少 3 场不同对话中被提及的；
- 其余事件线按 重要性 35% + 情绪强度 25% + 活跃度 25% + 回忆频率 15% 加权，竞争 20 个席位，进行中的事乘 1.5。

常驻期间不衰减、不参与扫描，每轮对话作为背景交给思考模型。

**用户画像**。稳定事实单独存放、不参与遗忘。用户前后说法矛盾时，按旧事实的牢固度掷骰子：重新唤起旧记录（两条都留，旧的会浮现出来）、覆盖（旧的移入档案）、或都不处理。

**新鲜记忆**。记忆系统启动后，上下文里不再有"聊天记录"这一项。刚说过的话也是记忆，只是强度几乎还是满的：强度不低于 0.9 的消息稳定在场。长时间不停顿的对话中，在它们跌出 0.9 之前先整理一批，避免出现"不新鲜、也还没整理"的空档。

## 四、扫描与浮现

记忆不是被"检索"出来的，而是自己冒头。

1. **分区**：概率海按月份分区，常驻栏不参与。
2. **轮询**：扫描器像时钟指针，每分钟扫描一个分区。
3. **采样**：对分区里每个片段做一次伯努利采样：

```
p = 0.02 × σ((S + π − 0.6) / T)
P(命中) = 1 − e^(−p · Δt)
```

   - σ 是 sigmoid，0.6 是浮现阈值，0.02 是每分钟的浮现速率上限（最强、最相关的记忆约每 50 分钟浮现一次）；
   - **π：启动加成**（priming）。当前话题的关键词（jieba + BM25）和人物给相关片段"充电"，最多 +0.5。认知科学称之为扩散激活；
   - **T：温度**。专注于同一话题时 T = 0.1，采样更确定，强而相关的记忆集中浮现；闲聊时 T = 0.3，弱的、不太相关的记忆也有机会冒出来，对应"放空"时的随机联想；
   - 负面记忆在话题无关时概率最多打四折，避免 AI 总提用户的伤心事；
   - Δt 是距这个片段上次被扫描过去的分钟数。
4. **浮现区**：命中的片段进入浮现区。容量只有 4，对应人的工作记忆，新的挤掉旧的。
5. **说不说由思考模型决定**：浮现的记忆交给思考模型，由它结合当下语境决定要不要提，比如"突然想起你之前说过……"。清晰度低的，它可以说"有点印象但记不清"。

扫描速度本身就是参数：扫得慢，就是"过一会儿才想起来"。

## 五、遗忘阈值与档案库

强度跌破 **遗忘阈值 S = 0.1** 的片段：

1. 退出扫描，不再浮现；
2. 进入待清理队列；
3. 累计满 **20 个**处理一批：
   - 19 个（95%）**移入档案库**：从概率海里消失，但原文完整保留；
   - 随机 1 个（5%）做**关键词抽象**：只留下几个关键词，重新开始一条衰减曲线，像一段模糊的印象。
4. 一场对话的摘要随之重写得更抽象一层；全部遗忘后，摘要本身就是这场对话留下的残影。

**没有信息是被彻底删除的**，除非用户要求。用户说"把这件事忘掉"时，AI 会先确认是哪件事，再让用户选择：彻底删除（不可恢复），或存入档案库。

### 档案库检索（RAG）

档案库是这个系统里唯一的"检索"环节，对应 RAG 的检索部分：

- 用 jieba 中文分词 + BM25 排序，在已归档片段的标题和原文中检索（没有用向量嵌入：关键词检索对人名、物名更准，也不需要额外模型）；
- **只在用户明确要求时检索**（"帮我翻翻档案"）。AI 不会自己去翻，否则就退化成普通 RAG，失去"会遗忘"的意义；
- 档案库就存放在数据文件夹里（记忆库 `memory.db`），**数据文件夹可以在设置页自选位置**。

## 六、启动机制：熟悉期

系统不是一开始就启动的：

1. **熟悉期**：按普通方式聊天，全部聊天记录放进上下文；消息实时存档，防止中途离开丢数据。
2. **启动**：上下文用量达到上限的 **70%** 时，一次性整理全部对话：切段、打分、挂事件线、建立概率海。整理完所有记忆强度设为满格，平滑过渡，用户不会感到 AI 突然"失忆"。
3. **运行期**：每轮上下文只带 人设 + 常驻栏 + 浮现区 + 新鲜记忆；遗忘、浮现、整理在后台循环。

按设计，熟悉期本身就是冷启动的校准数据：用整段对话给用户建立情绪基线，再回头算每个事件的相对情绪强度（情绪基线还没实现，目前按 0 计算）。

## 七、双模型

| | 思考模型 | 潜意识模型 |
|---|---|---|
| 做什么 | 当下的对话、推理、决定说什么 | 切段、打分、挂事件线、调参、合并、关键词抽象 |
| 什么时候 | 每条消息 | 对话停顿后、夜间，后台批量 |
| 默认 | DeepSeek（云端 API） | Qwen 27B Q4（本地 Ollama） |
| 可换成 | 任意 OpenAI 兼容模型 | 任意 OpenAI 兼容模型，或其他本地模型 |

这对应"双系统"：思考模型是有意识的回忆和表达；潜意识模型像睡眠中的记忆巩固，不存储记忆，只调节巩固和遗忘的速度。公式由 Python 执行，模型只决定系数，并受护栏约束（限幅、日志、可回滚）。

### 配置需求

**思考模型（云端，推荐）**
- 一个 OpenAI 兼容的 API 密钥（默认 DeepSeek）；对话内容会发送给服务商。
- 上下文越长，熟悉期越长：上限 100 万 token 时，要聊到约 70 万 token 才启动记忆系统，后期每条消息的成本和延迟随之增加。

**潜意识模型（本地，推荐）**
- 默认 Qwen 27B Q4 量化，约需 **17 GB 显存**（如 RTX 3090 / 4090，24 GB）；
- 显存不足可换 7B～14B 模型（Q4 量化约 5～10 GB 显存），整理质量会下降，但有档案库原文兜底；
- 记忆整理完全在本机进行，聊天记忆不出本机；
- 也可以改用云端：在设置页把潜意识模型的提供方改成 OpenAI 兼容接口。没有显卡也能用，代价是记忆内容会发给服务商，且调用频繁会产生费用。

**运行环境**
- Docker（Windows / Mac 用 Docker Desktop），一条命令部署：NapCat（登录 QQ）+ AstrBot（机器人框架）+ 本项目；
- 一个 QQ 小号（非官方协议，有被风控的风险，请勿使用主号）。

## 八、设置页

所有参数都可以在本地设置页调整（`http://127.0.0.1:8791`）：遗忘曲线、记忆时钟、扫描与浮现、常驻栏、批量遗忘、档案库检索、启动比例、模型、数据文件夹等。每个专有名词旁有一个 ⓘ，悬停即显示解释和公式。

也可以：
- 单独关闭任一功能（如批量遗忘、夜间合并、联网搜索、识图）；
- 自定义"记住 / 忘掉 / 翻档案"的触发说法，停用默认的、加上自己的。

## 十、现状

已实现：以上全部记忆机制；QQ 接入与 Docker 部署；识图与读文件；联网搜索；限频下的自主行为（换头像、发说说）；设置页。

还没做：独立的情绪模块（目前情绪分由切段模型顺带给出，情绪基线暂按 0）；长期运行的评估，以及"像不像人"该怎么衡量。
