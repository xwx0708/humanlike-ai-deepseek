# 架构总图

> 状态：草案 v0（2026-10-27），由总纲对话起草，待用户确认。模块边界一旦确认，各模块对话才分头深入。

## 阶段与模型

- 现阶段：框架搭建。
- 思考模型（回应模块）：DeepSeek API。
- 潜意识模型（记忆模块）：本地 Qwen3.8-27B Q4，跑在 RTX 3090 上。
- 见决策日志 D9。

## 模块与职责

**回应**（思考模型）
- 处理"当下"：理解用户的话，组织回复
- 每轮查看记忆的浮现区，自己决定提不提起；需要时主动检索记忆、或请记忆模块去翻档案
- 参考情绪模块给出的当前情绪信息，决定语气
- 决定什么时候调用行动模块

**记忆**
- 概率海：带强度、按半衰期衰减的长期记忆
- 扫描器：分区扫描、启动加成、概率浮现，维护浮现区
- 潜意识（见 [01-记忆/潜意识.md](../01-记忆/潜意识.md)）：切段；修改遗忘曲线参数；遗忘后的归类、删减、模糊化
- 档案：被遗忘的原文；残影作为索引
- 用户画像：稳定事实，不参与遗忘

**情绪**
- 给事件打分：唤醒度、效价、重要性
- 维护用户的长期情绪基线和短期心情
- 以后可扩展：AI 自身的情绪和性格

**行动**
- 通过 MCP 等协议调用外部工具
- 把"做过什么、结果如何"交还给回应模块，并作为事件交给记忆模块

## 数据流（草案）

```
用户消息 ──▶ 回应 ──▶ 回复给用户
               │ ▲
     调用工具  │ │ 浮现区 / 检索结果
               ▼ │
             行动 ─(做过的事)─▶ 切段（记忆·潜意识）──▶ 情绪打分 ──▶ 记忆写入
                                  ▲                                     │
对话记录 ─────────────────────────┘                                     ▼
                                                              概率海 / 档案
每条消息 ──▶ 情绪（实时粗略情绪）──▶ 回应
```

## 需要先定的边界问题

1. **情绪打分归谁？** 现在的记忆设想文档里包含"情绪打分系统"和"情绪基线"两节。建议移到情绪模块：情绪模块产出分数，记忆模块只拿分数来计算半衰期和浮现概率。
2. ~~**事件切分归谁？**~~ 已定（决策 D6）：归记忆模块的潜意识，方案见 [01-记忆/事件切分.md](../01-记忆/事件切分.md)。每条消息的实时粗略情绪归情绪模块。
3. **后台时钟归谁？** 扫描器、潜意识整理、基线更新都在后台运行，需要一个统一的调度和时间来源（也方便模拟时间做测试）。
4. **"熟悉期 → 启动 → 运行期"这个生命周期是全局的，还是只属于记忆模块？** 情绪基线也依赖它。
