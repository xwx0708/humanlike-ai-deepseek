## 模型调用 ChatModel（已实现）

定义在 `src/contracts/llm.py`，实现在 `src/llm/`。各模块只依赖这个接口，不直接调用某家的 API。

```python
from llm import thinking_model, subconscious_model   # 默认：DeepSeek / 本地 Qwen，可配置
from contracts.llm import system, user

reply = subconscious_model().chat([system("..."), user("...")], schema={...JSON Schema...})
reply.data      # 给了 schema 时：解析好的 dict（已检查 required 字段）
reply.text      # 正文
reply.reasoning # 开启思考时的思考过程，仅供调试
```

- 失败一律抛 `LLMError`：网络、鉴权、超时、输出不是合法 JSON、缺字段、被长度上限截断。网络错误、限流和服务端错误会自动重试。
- 测试时用 `llm.FakeModel` 代替真模型：按顺序返回预设回答，并记录每次收到的请求。
- **两个角色用什么模型都可以**（决策 D13）：`THINKING_PROVIDER` / `THINKING_MODEL`、`SUBCONSCIOUS_PROVIDER` / `SUBCONSCIOUS_MODEL`，提供方目前可选 `deepseek`、`ollama`；也可以直接用 `llm.make_model(provider, model)`。
- 配置项（环境变量或根目录 `.env`）见 `.env.example`。

## 片段、对话、事件线

三层结构的含义见 [术语表](术语表.md) 和 [01-记忆/事件切分.md](../01-记忆/事件切分.md)。由记忆模块的潜意识负责切分。

**已实现**：数据结构在 `src/contracts/memory.py`（Conversation、ChatTurn、EmotionScore、Segment、Thread、Person），存储见 [01-记忆/存储与提示词.md](../01-记忆/存储与提示词.md)。下面的表格是字段的说明。

**片段 Segment**（记忆和情绪共同的数据单位）

| 字段 | 说明 |
|---|---|
| id | 唯一标识 |
| 所属对话 | 一场对话的 id |
| 消息范围 | 包含哪些消息；一条消息可以同时属于两个片段 |
| 标题 | 一句话概括 |
| 涉及人物 | 人物 id 列表（经人物别名表归一，"我妈""母亲"是同一个 id） |
| 时间范围 | 开始、结束时间（真实时间） |
| 原文引用 | 指向档案里的原文 |
| 来源 | 用户对话 / AI 行动 / 熟悉期整理 |

**一场对话 Conversation**：id、时间范围、片段列表、片段之间的"接着聊到"关系（是图，不是链）、摘要。

**事件线 Thread**：id、标题、一句话摘要、片段列表、涉及人物、与其他事件线的关联。

**人物别名表**（记忆模块维护）：人物 id → 所有叫法（妈妈 / 我妈 / 老妈 / 母亲）。由切段第二层打分时顺便输出。

## 实时粗略情绪 QuickMood（情绪 → 回应）

每条消息一个，供 AI 心情使用。不调用思考模型。字段待定，至少包含唤醒度和效价的粗略值。

## 情绪打分与基线：记忆和情绪衔接的地方（D27）

定义在 `src/contracts/emotion.py`。情绪模块实现，记忆模块在整理时调用：

```python
class EmotionScorer(Protocol):
    def score(self, text: str, title: str) -> EmotionScore: ...   # 片段原文、一句话标题 → 峰终定律打分
class EmotionBaseline(Protocol):
    def arousal_baseline(self, ts: float) -> float: ...           # 某时刻的长期唤醒度基线 0～1
```

`memory.subconscious.consolidate(..., scorer=, baseline=)` 接收它们；不传时用暂行做法（切段提示词打分、`ZeroBaseline`）。

## 公共运行时（各模块共用，D27）

- `runtime.clock`：`Clock` 协议、`SystemClock`、`FakeClock`（测试模拟时间）。
- `runtime.scheduler.Scheduler`：`add(名字, 间隔秒, fn(now))` 登记定期任务；一个任务出错不影响别的。
- `runtime.lifecycle.Lifecycle`：`phase`（熟悉期 / 运行期）、`on_start(模块, fn(now))` 登记启动步骤、`maybe_start(now, 上下文用量, 上限)`。

## 情绪评分 EmotionScore（情绪 → 记忆）

对一个确认后的片段，按峰终定律打分。记忆模块在事后确认时调用。

| 字段 | 范围 | 说明 |
|---|---|---|
| arousal 唤醒度 | 0～1 | 绝对值；减去基线后的相对值由谁计算待定 |
| valence 效价 | -1～1 | |
| importance 重要性 | 0～1 | 与情绪无关的"不能忘" |
| reason 理由 | 文本 | 方便调试和人工检查 |

## 记忆条目 MemoryItem（记忆模块内部，列出来供参考）

内容、时间、唤醒度、效价、重要性、强度、半衰期、回忆次数、最近回忆时间、分区、档案链接。

## 浮现内容 SurfacedMemory（记忆 → 回应）

| 字段 | 说明 |
|---|---|
| 内容或残影 | 模糊程度不同 |
| 清晰度 | 让回应模块能说出"有点印象但记不清" |
| 效价 | 负面记忆除非话题相关，否则不主动提 |

## 常驻栏（记忆 → 回应，D17）

`memory.resident.resident_block(store)` 返回一段文字：用户画像 + 常驻事件线（标题和一句话摘要），开头说明"作为背景知道就好，不必刻意提起"。回应模块每次组织提示词时放进去。

## 记忆使用回执（回应 → 记忆）

回应模块真正提起或用到某条记忆时，调用 `memory.scanner.use_memory(store, 片段 id, 时间)`：强度回满、半衰期加长（D20），回忆次数加一。仅仅浮现不算。

## 浮现区与主动检索（记忆 → 回应，待办 #9）

- 浮现区：`memory.scanner.Scanner`；回应模块每轮看 `scanner.buffer`（最多 4 条 `Surfaced`：片段 id、文字、清晰度、效价），自己决定要不要提起。话题变化时调用 `scanner.set_topic(文字, 人物 id)`。每条用户消息后调用 `scanner.set_focus(focus_of(store, 对话 id))`：专注时低温、闲聊时发散（D26）。
- 主动检索：`memory.scanner.search_memory(store, 查询, 时间)`，只搜记忆系统。

## 档案与忘掉（回应 ↔ 记忆，D25）

- 用户要求忘掉某件事时，回应模块要先问用户选"彻底删除"还是"存进档案"，再调用 `memory.archive.forget_thread(store, 事件线 id, 方式, 时间)`，返回一句可以转告用户的说明。认出"用户要求忘掉/修改哪件事"由回应模块在对话中完成（待办 #17）。
- 用户要求找旧事时（只在用户要求时，AI 不自己翻，D26）：`memory.archive.search_archive(store, 查询)`，找回后 `restore_segment(store, 片段 id, 时间)`。

## 生命周期（D24）

`runtime.lifecycle.Lifecycle().phase` 返回"熟悉期"或"运行期"（全局，D27）。熟悉期里回应模块把全部对话放进上下文；运行期不另带聊天记录，只放常驻栏 + 浮现区 + 新鲜记忆（D30：本场对话就是几乎未衰减的记忆）。

## 新鲜记忆（记忆 → 回应，D30）

运行期每轮调用 `memory.fresh.fresh_memories(store, 时间)`，得到还没整理、强度不低于 0.9 的消息（按先后，含用户和 AI 说的），用 `fresh_block(...)` 变成一段文字放进提示词。它们稳定在场，不靠浮现；和浮现区不会重复。熟悉期不用（上下文就是全部聊天记录）。

## 任务时段（行动 → 记忆，D21）

智能体处理用户布置的任务时，记忆时钟照常流动。行动模块在任务开始和结束后调用 `MemoryStore.add_busy_span(start_ts, end_ts, note)`。格式暂定，行动模块开工时再确认。
