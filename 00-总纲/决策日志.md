# 决策日志

> 已经定下来的事。每条写明日期、决定、理由。推翻旧决定时新增一条，旧条目保留不删。

## 2026-10-27

**D1 长上下文不是方向**
- 决定：不靠更长的上下文追求"像人"。上下文只作为"当下"的工作区，长期记忆另外搭建。
- 理由：人不会同时摊开海量上下文，而是从海量长期记忆中按需浮现。（用户的原始设想）

**D2 记忆架构采用第三版**
- 决定：思考模型自己主动检索记忆；潜意识只负责维护记忆库。
- 理由：职责单一，不拖慢对话，记忆库状态确定、便于调试。（记忆设想文档"架构"一节的定稿）

**D3 多对话通过共享文件协作**
- 决定：每个模块由一个对话负责；所有协调通过本文件夹里的文件完成；接口只由总纲对话修改。
- 理由：对话之间看不到彼此的聊天记录。

**D4 权限：全部可读，只能改自己的区域**
- 决定：所有对话可以读取全部文件，只能修改自己负责的区域。除此之外不限制，鼓励主动使用工具。
- 理由：用户的要求。

**D5 代码规范由总纲对话制定**
- 决定：用户不另定代码规范，由总纲对话起草 [代码规范.md](代码规范.md)，用户确认后执行。

**D6 事件切分方案**
- 决定：采用用户的切段方案。切段是记忆模块潜意识的工作，思考模型不参与；"实时规则标候选 → 本地小模型事后确认 → 连成事件线"；结构分为事件线、一场对话、片段三层，片段是打分和遗忘的基本单位。方案和补充意见见 [01-记忆/事件切分.md](../01-记忆/事件切分.md)。
- 术语："事件"拆为"片段""一场对话""事件线"，见 [术语表](术语表.md)。
- 理由：不增加对话延迟和费用；便宜的规则保证不漏，小模型保证准确。

**D7 潜意识的职责**
- 决定：潜意识负责切段和修改函数参数（另外沿用设想文档中的遗忘后整理）。它只能修改遗忘曲线公式的参数，不能改公式结构；所有调整都要限幅并记录日志。见 [01-记忆/潜意识.md](../01-记忆/潜意识.md)。
- 理由：用户的要求。与 D2 一致：思考模型负责当下，潜意识在后台维护记忆库。
- 未定：全局参数是否允许潜意识自己修改（已由 D8 决定）。

**D8 全局参数也由潜意识修改**
- 决定：全局参数允许潜意识自己改，但要窄幅、慢速、留日志。暂定规则：单次 ±10%，范围为默认值的 1/1.5～1.5 倍，同一参数间隔至少 7 天，所有请求（包括被拒绝的）都记日志；小模型不能修改自身的调整上限。实现见 `src/memory/tuning.py`。
- 理由：用户的要求。窄幅和慢速让一次误判的影响有限，日志让问题可以被发现、可以回滚。

**D9 模型选型**
- 决定：思考模型调用 DeepSeek API；潜意识模型使用本地 Qwen3.8-27B（Q4 量化），跑在用户的 RTX 3090（24GB 显存）上。
- 理由：与设想文档"本地还是 API"一节的推荐组合一致：对话质量靠 API，潜意识的工作离线、批量、私密，适合本地模型。
- 现阶段：项目处于框架搭建阶段。
- 本机情况（2026-10-27 查看）：Qwen 由 Ollama 0.40.11 提供，模型名 `qwen3.8:27b-q4_K_M`（17GB），本地地址 http://127.0.0.1:11434。3090 有 24GB 显存，加载模型后约剩 7GB 给上下文；本机另有一块 RTX 5060 笔记本显卡（8GB），可以考虑让嵌入模型跑在那块卡上。（已由 D10 取代：不使用嵌入模型。）
- 注意：按[代码规范](代码规范.md)，两种模型都经过统一的调用接口，以后可以替换，测试时可以用假模型代替。（已由 D11 实现。）

**D10 不使用嵌入模型：语义判断归潜意识模型，数值计算归硬公式**
- 决定：系统不使用嵌入模型。需要理解语义的判断（切段时话题是否变化、片段属于哪条事件线）由潜意识模型 Qwen 完成；遗忘曲线等函数是硬公式，只做数值计算，参数由 Qwen 修改。切段第一层只保留不需要语义的规则（时间间隔、长度上限、语言信号）。连事件线时先用硬规则筛出最多 20 条候选（最近活跃、人名/称谓重合、jieba + BM25 关键词重合、高情绪高重要性常驻、档案人名强匹配），再交给 Qwen 判断，配合人物别名表和夜间合并。见 [01-记忆/事件切分.md](../01-记忆/事件切分.md)。
- 理由：用户的计划。不多占显存、不多依赖一个模型；语义交给 Qwen，数值交给可预测、可调试的公式。

**D11 统一的模型调用接口**（2026-10-28）
- 决定：所有模型调用都经过 `contracts.llm.ChatModel`，实现放在 `src/llm/`（归总纲）。思考模型默认 `deepseek-flash`；潜意识模型为 Ollama 上的 `qwen3.8:27b-q4_K_M`。只用 Python 标准库发 HTTP 请求，不加依赖。见[接口约定](接口约定.md)。
- **两种模型的"思考"默认都关掉**：实测 `deepseek-flash` 默认先思考再回答，思考内容也占 `max_tokens`，曾把 60 个 token 全部用完、导致 JSON 被截断；Qwen 做结构化判断时也不需要思考。需要时用 `DEEPSEEK_THINKING=true` 或构造参数打开。
- Ollama 的模型保持加载 30 分钟（首次加载约 1.5 分钟，之后每次调用约 0.7 秒），上下文长度 16384。
- 理由：代码规范要求模型可替换、测试不联网；关掉思考让回复更快，也避免结构化输出被截断。

**D12 存储用 SQLite，潜意识三个提示词落地**（2026-10-28）
- 决定：记忆存储用 SQLite 单文件（`data/memory.db`，不进版本库），消息原文永久保存即为档案。潜意识的三个提示词（切段第二层、判断事件线归属、修改函数参数）已实现，模型输出一律经 Python 校验和护栏后才写入。判断类任务温度设为 0；事件线把握低于 0.6 时新建；同一轮整理中每条旧记忆最多调整一次。见 [01-记忆/存储与提示词.md](../01-记忆/存储与提示词.md)。
- 理由：SQLite 是标准库、可查询、单文件；校准中发现的问题（重要性偏高、事件线标题不概括、重复加码等）已逐一修正并记录。

**D13 思考模型和潜意识模型都可以用任何模型**（2026-10-28）
- 决定：保留通用的模型调用接口；两个角色各自用哪家（provider）、哪个模型（model），都由配置决定，可以随意搭配甚至对调（`THINKING_PROVIDER`、`THINKING_MODEL`、`SUBCONSCIOUS_PROVIDER`、`SUBCONSCIOUS_MODEL`，见 `.env.example`）。默认仍是思考模型用 DeepSeek、潜意识模型用本地 Qwen（D9）。不在代码里限制潜意识只能用本地模型。
- 理由：用户的要求。代码只认角色，不认具体模型；新增一家时只需在 `llm.make_model` 加一个分支。

**D14 切段第一层规则与事件线摘要**（2026-10-28）
- 决定：第一层规则已实现（`src/memory/boundaries.py`）：距上一条超过 30 分钟开新对话；句首"对了""话说"等、句中"换个话题""说回"等语言信号（只看用户的消息）；跨零点只标候选、不拆对话；从上一个候选边界起满 30 条或 60 分钟强制标一次。阈值暂定。对话结束（安静超过 30 分钟或已开新对话）时，给最后一个片段补上首尾加成，只生效一次。片段挂到已有事件线后，由潜意识模型更新这条线的一句话摘要（标题一般不改）。
- 理由：补齐从"一条消息进来"到"挂上事件线"的完整链路；已用真实模型跑通三场对话。
