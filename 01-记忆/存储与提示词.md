# 存储与提示词

> 状态：v1 已实现（2026-10-28）。代码：数据结构 [src/contracts/memory.py](../src/contracts/memory.py)，存储 [src/memory/store.py](../src/memory/store.py)，提示词 [src/memory/prompts.py](../src/memory/prompts.py)，整理流程 [src/memory/subconscious.py](../src/memory/subconscious.py)。

## 一、存储

SQLite 单文件，默认 `data/memory.db`（不进版本库）。只负责存取，不做判断。

| 表 | 存什么 |
|---|---|
| conversations | 一场对话：开始、结束时间、摘要 |
| turns | 每条消息原文。**这就是档案**：原文永久保存，遗忘只影响片段 |
| boundaries | 切段第一层标出的候选边界及原因 |
| segments | 片段：标题、情绪评分、遗忘曲线状态（半衰期、最近回忆、回忆次数、调整倍数、首尾、状态、残影） |
| segment_turns | 片段包含哪些消息（多对多：一条消息可以属于两个片段） |
| segment_links | 片段之间"接着聊到"的关系（是一张图） |
| threads、thread_segments、thread_links | 事件线、挂了哪些片段（附把握值）、事件线之间"有关" |
| people、aliases | 人物别名表：妈妈 / 我妈 / 母亲 → 同一个 id；发现两个人其实是同一个时自动合并 |
| profile_facts、profile_sources | 用户画像：稳定事实（过敏、家人、职业等），原文不改写、不遗忘；记出处片段和提及次数；被覆盖的移进档案（archived_ts） |
| profile_conflicts、evocations | 画像矛盾的处理日志；被唤起、等待浮现的旧事实（D16） |
| threads.ongoing、threads.resident_since、resident_log | 事件线是否在进行中；何时进入常驻栏；常驻栏进出日志（D17） |
| global_knobs | 当前的全局参数 |
| tuning_log | 调参日志：每次请求都记，包括被限幅、被拒绝、本轮已调整过的 |

时间存 Unix 时间戳（秒）；调参日志沿用遗忘曲线的单位"天"。事件线合并时不删除旧线，只标记 `merged_into`，便于追溯。

## 二、潜意识的六个提示词

每个任务由三部分组成：提示词、约束输出格式的 JSON Schema、Python 校验。**模型的输出一律不直接信任**：越界数值收回范围，不存在的 id 丢掉，漏掉的消息并到前面的片段。

| 任务 | 输入 | 输出 | 校验 |
|---|---|---|---|
| 切段第二层 | 一段消息（带编号、时间、候选边界）、上一个片段的标题 | 片段列表：消息编号、一句话标题、人物及别名、唤醒度、效价、重要性、理由 | 编号越界的丢掉；漏掉的消息补进前面的片段；分数收回范围 |
| 判断事件线归属 | 新片段（标题、人物）、候选事件线卡片 | 事件线 id 列表或新建、新线标题、有关的线、把握值、理由 | 不在候选里的 id 丢掉；把握低于 0.6 改为新建，原先想挂的线记成"有关" |
| 修改函数参数 | 新片段、同一事件线上的旧记忆卡片、当前全局参数 | 调整列表：范围（单条记忆 / 全局）、目标、倍数、理由 | 目标不存在的丢掉（目标里抄了整张卡片时只取编号）；不允许改的参数丢掉；再经过限幅护栏 |
| 更新事件线摘要 | 事件线标题、原摘要、最近 10 个片段（日期 + 标题） | 一句话摘要、新标题（一般留空） | 摘要为空时报错；新标题为空或超过 20 字时沿用原标题 |
| 判断画像事实是否矛盾 | 新事实、同一个人同一类的旧事实 | 矛盾的旧事实 id、理由 | 不存在的 id 丢掉；拿不准就不算矛盾 |
| 遗忘后提取关键词（D22） | 被留下的 5%：编号、标题、原文节选（300 字） | 每条 2～4 个关键词 | 不存在的 id 丢掉；每条最多 4 个、每个最多 6 个字；模型漏掉的用标题开头兜底 |

## 三、整理流程（对话停顿时运行）

0. （每条消息进来时）第一层规则分对话、标候选边界：`memory.boundaries.ingest_turn`。
1. 取出还没切段的消息 → 切段第二层 → 存片段、登记人物、连"接着聊到"。
2. 每个新片段 → 判断事件线归属 → 挂上已有的线，或新建一条；记录"有关"。
   挂到已有事件线时，更新这条线的摘要。
3. 每个新片段 → 拿同一事件线上的旧记忆 → 修改参数 → 经护栏写入，记日志。**同一轮整理中，每条旧记忆最多调整一次。**
4. 对话已经结束时，给最后一个片段补上首尾加成（只生效一次）。
5. 重新排常驻栏（D17）。
6. 低于遗忘线的片段攒够 20 条时，按到达遗忘线的先后取这一批 20 条：95%（19 条）移进档案，随机挑 5%（1 条）提取关键词、重新开始遗忘曲线（D22）。攒得多就分几批，余下的继续攒。

"过了多久"一律用记忆时钟量（D21）。修改参数时，只有所在事件已完结的记忆才能把系数调到 1 以下（D19）。

潜意识模型用什么由配置决定（决策 D13），默认本地 Qwen。

## 四、实测与校准（本地 Qwen3.8-27B，2026-10-28）

测试对话：半年前随口说"我妈最近老咳嗽"；今天说妈妈肺炎住院、因请假被老板警告、想辞职回老家、最后说"记住这个：我对花生过敏"。

| 发现的问题 | 改法 | 改后 |
|---|---|---|
| 随口一提的咳嗽被打了重要性 0.8，算出约 95 天半衰期 | 重要性给出五档锚点，强调"情绪强不等于重要" | 0.3，半衰期 34 天 |
| 事件线标题用了第一个片段的句子 | 没有候选时也问一次，让 Qwen 起"概括这件事"的标题 | "妈妈的健康""工作去留""个人健康与过敏" |
| 因妈妈住院而想辞职，被整个挂到了妈妈的线上 | 规则：主体是新的事就新建，引起它的线放进"有关" | 新建"工作去留"，关联"妈妈的健康" |
| 同一条旧记忆在一轮里被两个新片段重复加码（×3 后又到上限 ×5） | 每轮每条旧记忆最多调一次，其余记为"本轮已调整过" | ×3，第二次请求被拦下并记日志 |
| 模型把整张记忆卡片抄进了目标编号 | 只取开头的编号 | 正常识别 |
| 同样的输入，有一次没有提出调整 | 判断类任务温度设为 0 | 连续几次结果一致 |

耗时：切 16 条消息、归属 5 次、调参 3 次，共约 50～60 秒（后台运行，可以接受）。

**第二轮（完整链路，2026-10-28）**：三场对话（半年前咳嗽 → 今天住院、爬山、老板、辞职 → 六天后出院）经第一层规则自动分开，"对了，周末……"被标为候选边界。

| 发现的问题 | 改法 | 改后 |
|---|---|---|
| 一次把住院、取消爬山、老板不满揉成一个片段，标题用"并""同时"串起来 | 规则：标题需要用"并""同时"串几件事，就说明切得太粗 | 拆成住院、取消爬山、老板与辞职三个片段 |

摘要效果："他母亲先是咳嗽，后确诊肺炎住院，他请假陪护并取消爬山，现已出院恢复不错，下周复查。"

出院后潜意识的调整：把"住院"拉长 ×1.5（事情有了结局），把"取消爬山"缩短 ×0.5（临时安排已失效）。另一次运行中曾把旧的"咳嗽"缩短 ×0.5（理由：问题已解决）。**"事情解决后是否应该缩短相关记忆"是一个设计选择，待用户决定**（见[待办](../00-总纲/待办.md)）。

## 五、用户画像与事件线候选（2026-10-28）

**用户画像**（设想文档："名字、关键关系等稳定事实可单独存成用户画像，只能合并、不能改写，也不参与遗忘"）
- 切段提示词顺便输出 facts：说的是谁、类别（过敏与禁忌、长期健康、家人与关系、生日与纪念日、职业与学业、居住地、长期偏好、其他）、一句陈述。
- 只收稳定事实；不收一时的状态，也不收带相对时间的事。
- 同一个人、同一类、内容相同（忽略标点）的合并：提及次数加一、补充出处，原文不改。
- 画像没有半衰期；出处片段本身照常遗忘。
- **矛盾处理（D16，用户定）**：新事实和同一个人同一类的旧事实矛盾时（由潜意识模型判断，第五个提示词），按旧事实的牢固度掷骰子三选一：唤起（旧的进入待浮现列表）、覆盖（旧的移进档案）、都不。代码见 `memory/profile.py`。实测 6 组矛盾 / 不矛盾的判断全部正确。

**事件线候选**（用户方案的五种来源，代码见 `memory/candidates.py`）

| 来源 | 做法 |
|---|---|
| 最近活跃 | 最近更新的 8 条 |
| 人物重合 | 线上任一片段的人物和新片段重合（经别名表归一） |
| 关键词重合 | jieba 分词，对事件线的标题、摘要、片段标题做 BM25，取前 8 条 |
| 常驻 | 线上有唤醒度或重要性 ≥ 0.7 的片段 |
| 档案人名 | 新片段人物的每个叫法（至少 2 个字）在消息原文里出现过的事件线，包括已遗忘的片段 |

超过 20 条时：命中来源多的优先，其次最近活跃的优先（暂行）。

**实测**：住院片段对"妈妈的健康"命中四种来源，出院片段命中全部五种。画像抽出"对花生过敏""有一个妹妹叫小雨""在杭州做前端开发"；一开始误收"妹妹下个月结婚"，加了"不收相对时间"的规则后两次运行都正确排除。

## 六、常驻栏（D17，2026-10-28）

代码见 `memory/resident.py`。每次整理结束时重新计算：

| 情况 | 规则 |
|---|---|
| 免竞争，一直常驻 | 事件线上有用户画像的出处；有用户要求记住的片段（切段提示词判断）；出现在至少 3 场不同的对话里。一旦成立就记在 `threads.exempt`，之后即使条件不再满足也不退出；只有用户要求修改时用 `release_exempt` 解除，解除后照常竞争，不会被自动标回（D18） |
| 竞争 20 个名额 | 重要性 35% + 情绪强度 25% + 活跃度 25% + 回忆频率 15%；进行中的 ×1.5 |
| 落选 | 退回普通记忆池，照常遗忘；遗忘从最近一次被提及开始算 |
| 常驻期间 | 不遗忘（强度视为 1）；判断事件线归属时整栏给潜意识模型；`resident_block` 生成给思考模型的背景文字 |

**实测**："对了你记住，我对花生过敏，我妹妹叫小雨"被识别为要求记住，所在事件线免竞争常驻；"妈妈的健康""工作去留"竞争进入。发现并修正：画像里混进了"母亲近期因肺炎住院"（加相对时间硬规则）；新建事件线一律默认进行中（改为新建时判断）。
