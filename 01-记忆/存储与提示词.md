# 存储与提示词

> 状态：v1 已实现（2026-10-28）。代码：数据结构 [src/contracts/memory.py](../src/contracts/memory.py)，存储 [src/memory/store.py](../src/memory/store.py)，提示词 [src/memory/prompts.py](../src/memory/prompts.py)，整理流程 [src/memory/subconscious.py](../src/memory/subconscious.py)。

## 一、存储

SQLite 单文件，默认 `data/memory.db`（不进版本库）。只负责存取，不做判断。

| 表 | 存什么 |
|---|---|
| conversations | 一场对话：开始、结束时间、摘要 |
| turns | 每条消息原文。**这就是档案**：原文永久保存，遗忘只影响片段 |
| boundaries | 切段第一层标出的候选边界及原因 |
| segments | 片段：标题、情绪评分、遗忘曲线状态（半衰期、最近回忆、回忆次数、调整倍数、首尾、状态、残影） |
| segment_turns | 片段包含哪些消息（多对多：一条消息可以属于两个片段） |
| segment_links | 片段之间"接着聊到"的关系（是一张图） |
| threads、thread_segments、thread_links | 事件线、挂了哪些片段（附把握值）、事件线之间"有关" |
| people、aliases | 人物别名表：妈妈 / 我妈 / 母亲 → 同一个 id；发现两个人其实是同一个时自动合并 |
| global_knobs | 当前的全局参数 |
| tuning_log | 调参日志：每次请求都记，包括被限幅、被拒绝、本轮已调整过的 |

时间存 Unix 时间戳（秒）；调参日志沿用遗忘曲线的单位"天"。事件线合并时不删除旧线，只标记 `merged_into`，便于追溯。

## 二、潜意识的三个提示词

每个任务由三部分组成：提示词、约束输出格式的 JSON Schema、Python 校验。**模型的输出一律不直接信任**：越界数值收回范围，不存在的 id 丢掉，漏掉的消息并到前面的片段。

| 任务 | 输入 | 输出 | 校验 |
|---|---|---|---|
| 切段第二层 | 一段消息（带编号、时间、候选边界）、上一个片段的标题 | 片段列表：消息编号、一句话标题、人物及别名、唤醒度、效价、重要性、理由 | 编号越界的丢掉；漏掉的消息补进前面的片段；分数收回范围 |
| 判断事件线归属 | 新片段（标题、人物）、候选事件线卡片 | 事件线 id 列表或新建、新线标题、有关的线、把握值、理由 | 不在候选里的 id 丢掉；把握低于 0.6 改为新建，原先想挂的线记成"有关" |
| 修改函数参数 | 新片段、同一事件线上的旧记忆卡片、当前全局参数 | 调整列表：范围（单条记忆 / 全局）、目标、倍数、理由 | 目标不存在的丢掉；不允许改的参数丢掉；再经过限幅护栏 |

## 三、整理流程（对话停顿时运行）

1. 取出还没切段的消息 → 切段第二层 → 存片段、登记人物、连"接着聊到"。
2. 每个新片段 → 判断事件线归属 → 挂上已有的线，或新建一条；记录"有关"。
3. 每个新片段 → 拿同一事件线上的旧记忆 → 修改参数 → 经护栏写入，记日志。**同一轮整理中，每条旧记忆最多调整一次。**

## 四、实测与校准（本地 Qwen3.8-27B，2026-10-28）

测试对话：半年前随口说"我妈最近老咳嗽"；今天说妈妈肺炎住院、因请假被老板警告、想辞职回老家、最后说"记住这个：我对花生过敏"。

| 发现的问题 | 改法 | 改后 |
|---|---|---|
| 随口一提的咳嗽被打了重要性 0.8，算出约 95 天半衰期 | 重要性给出五档锚点，强调"情绪强不等于重要" | 0.3，半衰期 34 天 |
| 事件线标题用了第一个片段的句子 | 没有候选时也问一次，让 Qwen 起"概括这件事"的标题 | "妈妈的健康""工作去留""个人健康与过敏" |
| 因妈妈住院而想辞职，被整个挂到了妈妈的线上 | 规则：主体是新的事就新建，引起它的线放进"有关" | 新建"工作去留"，关联"妈妈的健康" |
| 同一条旧记忆在一轮里被两个新片段重复加码（×3 后又到上限 ×5） | 每轮每条旧记忆最多调一次，其余记为"本轮已调整过" | ×3，第二次请求被拦下并记日志 |
| 模型把整张记忆卡片抄进了目标编号 | 只取开头的编号 | 正常识别 |
| 同样的输入，有一次没有提出调整 | 判断类任务温度设为 0 | 连续几次结果一致 |

耗时：切 16 条消息、归属 5 次、调参 3 次，共约 50～60 秒（后台运行，可以接受）。

## 五、暂行做法（待办见 [00-总纲/待办.md](../00-总纲/待办.md)）

- 事件线候选：暂时取最近活跃的 20 条，正式的五种来源并集还没实现。
- 情绪基线：还没实现，暂按基线 0 计算相对唤醒度。
- 首尾加成：只标了一场对话的首个片段；末个片段要等对话结束时再标。
- 全局参数：整理流程里只在"有相关旧记忆"时调参；需要长期证据的全局调整还没有单独的流程。
- 情绪评分暂时放在切段提示词里一起输出，等"情绪打分归哪个模块"定了再决定是否拆分。
