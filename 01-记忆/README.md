## 总览

让聊天 AI 更像人，关键不是更长的上下文，而是一套会遗忘、会模糊、会自己浮现的记忆系统。整体由四部分组成：负责当下的思考模型，一片按概率存在的记忆库（概率海），在后台按公式运算、由小模型调节系数的潜意识，以及保存被遗忘原文的档案。系统在聊天初期不启动，等积累出用户的情绪基线后再接管。

下文中，标注"我的设想"的是原始想法，标注"补充"的是讨论中加入的参考与建议。

> 整体架构：思考模型只管当下和主动检索；记忆在扫描器中按概率自己浮现；潜意识在空闲时把低于遗忘线的记忆归类、删减、模糊化。

## 出发点：长上下文是错的方向

**我的设想**
- 在聊天这个领域，一味追求更长的上下文是走错了路。
- 目标始终是"更像人"，但没有人能在脑子里同时摊开 100 万字的上下文。
- 反过来，人的记忆里装着千万、亿万级别的"上下文"，只是不会同时拿出来。

**补充**
- 人的工作记忆一次只能处理约 4 个信息块，长期记忆却容量巨大、有损、会重构。
- 大模型正好相反：上下文是一字不差的完美短期记忆，长期记忆冻结在权重里，缺的是能持续写入、会遗忘、会重组的情景记忆。
- 长上下文并非无用：读代码库、审合同这类"超越人"的任务仍需要它。两者可以并存，上下文充当工作区，长期记忆另建。
- 需要取舍：用户未必想要会遗忘的 AI。情感陪伴类更适合本设想，工具类更依赖精确记忆。

## 核心理念：当下与非当下

**我的设想**
- 思考分为两部分：当下和非当下。
- 当下的事情集中处理。
- 非当下的事情是一片概率海：每段记忆不是"在或不在"，而是以某个概率存在、以某个概率被想起。
- 潜意识的工作，就是在这片概率海里以不同速率调低某些记忆，删除另一些。

**补充**
- 对应到实现：当下 = 上下文窗口（工作记忆）；非当下 = 带强度值的长期记忆库。
- 认知心理学的 ACT-R 架构几乎就是这个模型：每条记忆有激活值，随时间衰减、被回忆时提升，回忆时带随机噪声、按概率决定想起哪条。

## 记忆强度与情绪遗忘曲线

**我的设想**
- 在仿真聊天 AI 的数据中，给事件规定情绪值。
- 情绪值高的事件，其始末整体进入一条斜率很低的遗忘曲线，忘得很慢。
- 其他事件进入正常遗忘曲线。

**补充**
- 人脑中确有对应：杏仁核会增强情绪事件的记忆巩固，惊吓、狂喜的经历记得特别牢。
- 遗忘曲线即艾宾浩斯曲线，本设想相当于用情绪值调节曲线的半衰期。
- 每次被回忆都应加固记忆、重置曲线；反复被提起的事，即使情绪值低，也应忘得更慢。
- 一个简单的强度模型：强度 = 基础值 × 时间衰减 + 每次回忆的加成，衰减速率由情绪值决定。
- 每条记忆至少存：内容、时间、情绪值、重要性、被回忆次数、最近回忆时间。

### 情绪打分系统

- 情绪值是整个系统的"价值观"，决定 AI 在乎什么、记住什么。
- 两个维度：唤醒度（多强烈，0～1）决定记得牢不牢；效价（正负面，-1～1）不影响遗忘速度，只影响浮现概率。
- 重要性单独打分：平淡但不能忘的事（过敏、家人名字）靠重要性保住。
- 打分对象是事件：一段围绕同一件事的连续对话算一个事件；参考"峰终定律"，看最强烈的时刻和结尾，而不是平均值。
- 信号来源：字面内容；表达方式的变化（长短、标点、语气词、回复速度）；同一件事被反复提起；用户明确说"记住这个"则直接拉满。
- 打得稳：给小模型打分细则和锚点例子，输出固定格式（唤醒度、效价、重要性、理由），打两三次取平均，用人工标注的测试集检查漂移。
- 负面记忆：记得住，但除非话题相关，不主动冒头，避免 AI 总提用户的伤心事。
- 注意：反讽和含蓄表达容易判错；先只给用户的情绪打分，AI 自身情绪留作后期扩展；情绪档案高度私密。

### 情绪基线

**我的设想**：需要设立一个基础情绪值。用户和 AI 的对话既要影响基础情绪值，也要产出本事件的情绪值；本事件情绪要减去基础情绪值，得到真正用于计算的数值。

**补充**
- 先减，再更新：用更新前的基线计算本事件的相对值，算完再把本事件计入基线，否则强烈事件会先把基线拉高、显得自己不特别。
- 基线变得很慢：每个新事件只让它挪动一点点，并限制极端事件的影响。
- 两层基线：长期基线（以月计，代表性格）用于计算半衰期；短期心情（以天计，代表近况）不直接相减。短期心情明显偏离长期基线时，把这段时期本身记成一个事件，例如"十月那几周他情绪一直很低"。
- 唤醒度和效价各有基线，分开算。
- 低于基线不简单归零：平时外放的人突然冷淡简短，可以提高这件事的重要性分。
- 长期基线的变化轨迹本身也该存档，它记录了这个用户的变化。

### 半衰期怎么算

每条记忆有一个强度，刚记下时是满的，之后按半衰期变弱：每过一个半衰期，强度剩一半。强度掉到约十分之一时，这条记忆被"遗忘"，原文移入档案，概率海里只留残影。

半衰期从基础值出发（平淡小事约 7 天），被三个因素放大：

1. 相对情绪强度（本事件比长期基线高出多少）：越往高处放大得越厉害，有点情绪约 3 倍，最强烈约 10 倍。
2. 重要性：最多再放大约 5 倍，与情绪无关。
3. 小模型的调整：根据新信息拉长或缩短，单次和累积都有上限。

回忆加固：每被想起一次，半衰期变长；隔得越久再想起加固越多，最多一次翻倍，刚聊过又提几乎不加固。

大概效果：平淡小事约三周被遗忘；有点情绪的事约两个半月；很强烈的事约半年；极强烈的事七八个月。再叠加重要性或反复回忆，可以保留好几年。

需要调的旋钮只有四个：基础半衰期、情绪放大力度、重要性放大上限、回忆加固力度。

## 遗忘之后：归类、删除、模糊化

**我的设想**
1. 遗忘程度达到某个阈值的事件，统一被归类。
2. 每一类中清除掉 95%。
3. 剩下的 5% 进行抽象化、模糊化处理。

**补充**
- 这很像人脑把具体经历压缩成"要点"和"图式"：记得"小学常去那家小卖部"，却记不清任何一次买了什么。
- 删哪 95%：随机删更像人，但可能丢关键信息；按"与其他记忆的关联度"删更合理，孤立的细节先忘。
- 模糊化会产生"假记忆"，这既像人也可能是缺陷，需要决定取舍。
- 被删除的事件可保留一条极简"残影"，例如"十月初聊过一件不愉快的事，细节记不清"，让 AI 能说"有点印象但记不清"。
- 名字、关键关系等稳定事实可单独存成用户画像，只能合并、不能改写，也不参与遗忘。

## 档案层：遗忘不等于删除

**我的设想**
- 把思考部分和储存部分分开。思考部分完全按前面的设想运行，区别只在遗忘：遗忘照常发生，但数据不删除，而是从思考部分移到储存部分。
- 这样用户真想让 AI 回忆一年前的一件小事时，AI 可以明确告诉用户：我花点时间找一找。

**补充**
- 结构变成三层：当下（上下文）→ 概率海（自然聊天时"记得什么"）→ 档案（被遗忘的原文，平时碰不到）。像人脑忘了，但日记和聊天记录还在。
- 好处：遗忘可逆，不怕删错；模糊化产生的假记忆可以对照原文纠正；原文天然就是调试日志；"像人"和"好用"不必再二选一。
- 残影就是索引：概率海里的模糊残影带着指向档案原文的链接，先"隐约想起"，再顺着残影去翻。
- 翻档案要有门槛：只在用户明确要求，或 AI 判断"重要但记不清"时才翻，否则退化成普通 RAG。
- 翻找是慢动作：交给后台任务，AI 先回一句"我找找"，找到再说。
- 找回的记忆重新入海：强度提升，相当于回想一次记牢一点。
- 真正的删除权：用户要求"忘掉这件事"时，连档案一起彻底删除。

## 注意力的两种状态：专注与放空

**我的设想**
- 模拟人脑：人的注意力集中在当前发生的事情上。
- 放空时，注意力是弥散的。
- 设想的起点：把 AI 的注意力机制用在"内容"上，而不只是用在思考上。

**补充**
- Transformer 的注意力本身就是"基于内容"的：按相关度分配权重，它不思考，思考是多层叠加后涌现的。推理模型的"思考"最终也是写出来的内容，再被注意力回看。
- 放空时大脑的"默认模式网络"活跃，会随机联想旧记忆。
- 在概率海中，用一个温度参数统一两种状态：
  - 低温度：概率集中在最相关、最强的记忆上，即专注。
  - 高温度：概率被摊平，弱的、不太相关的记忆也可能浮现，即放空。
- 温度可随对话状态变化：认真讨论时调低，闲聊或长时间沉默时调高。

## 架构：从 RAG 到双模型

设想经历了三步演变，最终定为第三版。

### 第一步：RAG 作地基

- 普通 RAG 只解决"记得多"：永不遗忘、永不改变、平等对待每条记忆，像档案馆而不像人。
- 结论：用 RAG 做存储和检索底层，在上面加一层记忆管理（强度、遗忘、抽象化），这一层才是本设想的核心。
- 更远的方向是把记忆直接写进模型权重（持续学习），最接近人脑，但目前成本高、会"学新忘旧"。

### 第二步：两个模型，一个思考、一个潜意识

- 对应"双系统"理论：系统一快速、自动、无意识；系统二缓慢、刻意、有意识。
- 初版分工：潜意识检索记忆并加工成模糊"感觉"推送给思考模型，思考模型看不到记忆库。

### 第三步（我的定稿）：思考模型自己找记忆，潜意识只维护记忆库

- 思考模型：负责对话和推理，需要时主动检索记忆库。
- 潜意识模型：专门对思考模型检索的那个记忆库进行整理、裁剪、遗忘。
- 对应人脑：回忆是有意识的主动搜索，巩固和遗忘主要在睡眠中、在后台完成。
- 优点：职责单一、不拖慢对话、记忆库状态确定便于调试。
- 要点：检索要留下痕迹（被想起一次就记一次），供潜意识加固；整理在对话结束后或空闲时运行，避免边读边改。

## 记忆自己冒头：分区扫描与浮现区

**我的设想**
- 不是去"挑选"信息，而是让概率自己冒头。
- 潜意识慢慢地计算：算完这个分区，再算下一个分区。
- 数值运算可以用 Python 代码代替模型。

**补充：具体机制**

1. 记忆库按分区存放（按时间段或主题）。
2. 后台 Python 循环像时钟指针一样轮流扫描分区，对每条记忆：
   - 按情绪决定的半衰期衰减强度
   - 加上当下话题带来的"启动"加成（向量相似度，话题变化时算一次）
   - 按概率掷骰子，命中就放进浮现区
   - 强度低于遗忘线的，交给模型做归类、删除、模糊化
3. 浮现区容量很小（3～5 条，类似人的工作记忆），旧的会被挤掉。
4. 思考模型每轮看一眼浮现区，自己决定要不要提起，比如"突然想起你之前说过……"

核心计算：

```python
for m in partition:
    m.strength *= exp(-dt / m.half_life)        # 情绪越强 half_life 越长
    p = sigmoid((m.strength + priming(m) - threshold) / temperature)
    if random() < p:
        surface_buffer.push(m)                  # 自己冒头
    if m.strength < forget_line:
        to_abstract.append(m)                   # 交给模型模糊化
```

分工：Python 负责衰减、加固、概率抽样、阈值判断；模型只做需要理解语义的事——给新记忆打情绪值、把待遗忘的记忆抽象成模糊概括。

**特点**
- 扫描速度本身是参数：扫得慢，就"过一会儿才想起来"；扫得快，反应灵敏。
- 认知科学称之为"扩散激活"：当下话题给相关记忆充电，充够了就浮上意识。
- 保留兜底：对话急、相关记忆还没被扫到时，思考模型仍可主动检索。
- 记忆量大时先用向量检索粗筛，再在小范围内做概率计算。

## 潜意识的分工：公式与系数

**我的设想**：Python 用固定的公式随时间调低概率；小模型的任务是根据新信息去调整公式的系数。

**补充**
- 模型决定"规则"，Python 只负责"执行"。模型只在新信息进来时调用，次数少，本地小模型跑得动。对应人脑的神经调质：不存储记忆，只调节巩固和遗忘的速度。
- 最有价值的是回头改旧记忆：半年前随口提的"我妈最近老咳嗽"正在被遗忘，今天用户说"我妈住院了"，小模型就拉长那条旧记忆的半衰期，并把相关记忆连起来。
- 三层系数：单条记忆（半衰期、强度、关联）；类别（某类话题整体变快或变慢）；全局（温度、扫描速度、遗忘线）。
- 流程：新信息进来 → 向量检索找相关旧记忆 → 小模型输出结构化调整 → Python 校验后写入。
- 护栏：限幅（例如半衰期一次最多翻 3 倍）、平滑累积、记录每次调整的日志；模型只能改系数，不能改公式结构。

### 本地还是 API

- 概率海的大部分运算是 Python，不需要模型。需要模型的只有：打情绪分、归类、模糊化、调系数。
- 这些任务离线、批量、不赶时间、相对简单，适合本地 7B～14B 级别的小模型；调用频繁，本地几乎零成本；记忆高度私密，留在本地更安心。嵌入模型也可放本地。
- 代价：需要显卡或接受 CPU 慢跑；小模型模糊化更易出错，但有档案层兜底。
- 推荐组合：思考模型用 API（对话质量最重要）；潜意识用本地小模型 + Python；关键或高情绪记忆的模糊化可单独调用一次 API 大模型。
- 原型阶段可以先全用 API 跑通，机制稳定后再换本地。

## 启动时机：熟悉期

**我的设想**：开始时先不启动系统，在上下文限制内正常聊天；等积累出一个情绪值，也就是快到上下文极限时，再启动系统。

**补充**
- 冷启动问题自然解决：整段上下文就是校准基线的数据。启动时一次性切分事件、打分、用全部数据算基线，再回头算每个事件的相对值。
- 不启动不等于不保存：熟悉期也要实时把原文存进档案，防止用户中途离开导致数据丢失。
- 留余量：用到上下文七八成就启动；聊得少但已跨越很多天时也该启动。
- 初始基线是暂定的：启动后一段时间基线更新得快一些，数据多了再放慢。
- 平滑过渡：最近的对话留在上下文，较早的转入概率海，且初始强度满格，用户不会感到 AI 突然失忆。
- 三个阶段：熟悉期（正常聊天、全部存档）→ 启动（整理全部对话、算基线、建立概率海）→ 运行期（遗忘、浮现、整理循环）。

## 待解决的问题

最值得先想：事件怎么切分（决定整个系统的数据单位），以及怎么评估"像不像人"（决定所有调参的方向）。

**记忆本身**
- 一个事件的边界怎么划？跨好几天断续聊的同一件事怎么连起来？
- 记忆存成什么形式：原文、摘要，还是结构化的"谁、何时、什么事、什么情绪"？
- 记忆之间的关联怎么建立？"想起一件带出另一件"需要关联网络。
- 用户前后矛盾、改口时，以哪个为准？
- AI 自己说过的话、做过的承诺要不要记？

**时间**
- 遗忘按真实时间还是按对话次数？用户三个月没来，回来时是否该淡忘一切？
- AI 怎么感知距离上次聊天多久，并自然体现？

**思考模型的行为**
- 如何区分"我忘了"和"我从来不知道"？
- 浮现的记忆什么时候说出口，什么时候只默默影响语气？
- 被纠正"你记错了"之后，记忆怎么更新？

**AI 自己**
- AI 有没有自己的情绪或性格？会不会影响它记住什么？
- 换了思考模型或打分模型后，旧记忆和新标准怎么保持一致？

**参数与工程**
- 四个半衰期旋钮、基线更新速度、温度、扫描速度怎么调？要不要先做一批模拟用户跑长期对话？
- 概率抽样让行为难复现，测试时固定随机种子。
- 小模型打分和模糊化出错时，用档案原文校正的流程怎么设计？

**用户与伦理**
- 用户能否查看、修改 AI 对他的记忆？
- 要求"彻底忘掉"时，如何保证概率海和档案都删干净？
- AI 越像人，用户越可能产生情感依赖，要不要设限？
